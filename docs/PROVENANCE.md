paths, account names, and internal coordination identifiers.

## What the 1.1.0 change did to the frozen core

The 1.0.0 core was byte-frozen at engineering checkpoint M4-019G. Four modules
changed in 1.1.0 — `document.py`, `engine.py`, `question.py` (the segmentation
and typed-answer work) and `fetch.py` (the user-agent string, which read
`SourceCourt-Exact-Lite/0.1` in 1.0.0). This was
a deliberate, owner-authorized version increment, not a rewrite of accepted
bytes: the 1.0.0 source and artifacts remain preserved and unmodified, and
1.1.0 carries its own hashes in [`RELEASE_MANIFEST.md`](RELEASE_MANIFEST.md).

The security behaviour accepted at M4-019G is unchanged, and the security tests
were not edited to accommodate the change.

The 1.0.0 build hard-coded its `User-Agent` as `SourceCourt-Exact-Lite/0.1`
while shipping as version 1.0.0. 1.1.0 derives the header from the package
version instead, and a test asserts that the two agree.

## The published answer defect (why 1.1.0 exists)

The 1.0.0 live demonstration asked *"What is the reserved top-level domain for
testing?"* against a plain-text RFC and returned

```text
domain names are reserved for use in private testing, as examples in
```

— a line of the RFC, cut mid-sentence. Two independent defects produced it:

1. **Segmentation:** the splitter treated every newline as a sentence boundary,
   so a hard-wrapped document produced one "sentence" per physical line.
2. **Selection:** keyword overlap alone ranked a section about confusion in
   experimentation and testing above the passage that actually names the
   reserved domain.

1.1.0 fixes both: paragraphs are unwrapped and split on real sentence
boundaries, and a question that asks for an identifier value selects a passage
satisfying the question's condition and answers with the value itself
(`.test`), quoting the full sentence as evidence. Regression tests cover the
report, the discriminating decoys (`.example`, `.invalid`, `.localhost`), four
other value kinds, and the refusal paths.

## Workspace anomaly in the earlier history (recorded, not concealed)

During the original build of 1.0.0, that build workspace was co-occupied by a
second automated actor working the same milestone. Both lines ended up in one
repository, which is why the private history contains an alternate operator CLI
(`run` / `serve` / `verify`) and a receipts experiment.

What was established then and re-verified:

- The certified 1.0.0 wheel and the pre-correction source distribution were
  preserved byte-exact across that actor's restructure.
- The accepted core modules were not modified by it: their recorded hashes held.
- No repair or mutation of the other actor's files was performed; the anomaly
  was audited rather than quietly cleaned up.
- The final 1.0.0 sdist was produced after one self-consistency correction to
  its own acceptance record, which is why an intermediate sdist hash appears in
  the contemporaneous audit note and the final hash in the certified manifest.
  Both are recorded facts; neither hides the other.

## Test evidence

The superseded operator line's suite is not part of the product and is not run
here; its execution evidence remains in the private history. This repository
runs the product's own suite — 85 tests shipped in the sdist plus 14
release-integrity tests, 99 in total — and [`VERIFICATION.md`](VERIFICATION.md)
records the measured results. No test was deleted for a green count, no assertion weakened,
and no skip or expected-failure marker exists anywhere in the suite.
